# DueGuard QA / Test Cases

사람이 바로 디바이스에서 수행할 수 있는 체크 리스트. 자동화된 유닛 테스트로도 동일 항목을 커버해야 하지만, **릴리스 전 실기 검증 우선**.

기호:
- [D] Device QA (실기로 확인)
- [U] Unit/Integration test로도 커버 (Dart 로직 테스트 가능)
- [L] Locale 둘 다(ko/en) 돌려볼 것

## 0. 설치 & 권한

| # | 시나리오 | 기대 결과 | 유형 |
|---|---|---|---|
| 0-1 | 앱 최초 실행 | 홈 화면 진입, 알림 권한 즉시 요청 안 함 | [D] |
| 0-2 | 첫 항목 저장 직후 | 알림 권한 요청 다이얼로그 노출 | [D] |
| 0-3 | 권한 거부 상태로 홈 진입 | 상단에 "알림이 꺼져 있습니다" 배너 노출, 설정 딥링크 버튼 | [D][L] |
| 0-4 | 권한 허용 후 홈 복귀 | 배너 사라짐 | [D] |

## 4. Past time scheduling

| # | 시나리오 | 기대 결과 | 유형 |
|---|---|---|---|
| 4-1 | once 항목을 과거 시각으로 저장 | 확인 다이얼로그. 확인 시 저장되지만 알림 미예약. 홈에서 "기한 지남" 배지 | [D][U] |
| 4-2 | daily 항목을 과거 시각으로 저장 | dueAt이 다음 유효 회차로 전진해 저장, 알림 예약 | [U] |
| 4-3 | 앱을 30일간 미실행, 그 사이 monthly 항목 다수 회차 통과 | 앱 실행 시 각 항목의 dueAt이 현재 이후 첫 회차로 전진 후 재예약 | [D][U] |
| 4-4 | 4-3에서 once 항목이 포함되어 있음 | 해당 once 항목은 "기한 지남" 표시. 알림 미재예약 | [D][U] |

## 5. 알림 전달/재예약

| # | 시나리오 | 기대 결과 | 유형 |
|---|---|---|---|
| 5-1 | 2분 뒤로 once 항목 저장 | 2분 뒤 실제로 알림 수신 | [D] |
| 5-2 | 5-1 이후 항목의 날짜를 10분 뒤로 수정 | 기존 알림 취소, 10분 뒤 알림 수신. 원래 2분 뒤에 알림이 울리지 **않아야 함** | [D] |
| 5-3 | 5-2 이후 항목 삭제 | 알림 수신 안 됨 | [D] |
| 5-4 | 2분 뒤 알림 예약된 항목이 있는 상태로 기기 재부팅 | 부팅 후 알림이 여전히 수신됨 (flutter_local_notifications가 AlarmManager 기반으로 살아있어야 함) | [D] |
| 5-5 | 알림 탭 | 앱이 열리고 해당 항목 상세로 이동 (또는 최소 홈으로 이동) | [D] |
| 5-6 | 동일 항목을 빠르게 3회 수정 저장 | 최종 알림 1개만 예약됨. 중간 상태 알림이 남아있지 않음 | [D][U] |

## 유닛 테스트 최소 커버리지 목표
- `repeat_rule.dart` (또는 동급 로직): 위 표의 [U] 항목 전부 커버.
- `notification_scheduler.dart` (또는 동급): 취소→재예약 순서, past-time 처리 로직 커버.
- 첫 릴리스 기준 **유닛 테스트 케이스 25개 이상** 목표.
