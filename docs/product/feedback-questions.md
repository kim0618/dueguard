# DueGuard Feedback Questions (7일차 설문)

내부 테스트 7일 종료 시점에 테스터에게 묻는 질문 10개.
"돈 나가는 날짜 관리"라는 포지션이 맞는지, 알림이 신뢰되는지,
7일 재방문이 유지되는지를 검증하는 것이 목표.

## 형식
- 1~10번 모두 필수
- 1~5: 5점 척도 (1=전혀 그렇지 않다, 5=매우 그렇다)
- 6~10: 주관식

---

## Q1. 첫 항목 등록 속도 (척도)
**"앱을 처음 연 뒤 첫 항목을 등록하기까지 15초 안에 끝났다."**

15초 목표의 실제 검증. 1~2점이 많으면 폼/권한 흐름을 손봐야 한다.

## Q2. 알림 신뢰도 (척도)
**"예약한 시각에 실제로 알림이 왔다."**

알림이 늦게 오거나 빠졌는지. 4점 미만이면 critical.

## Q3. 포지션 이해도 (척도)
**"이 앱은 '놓치면 돈이 나가는 일정'을 관리하기 위한 앱이라는 것이 명확했다."**

포지션 전달이 되는지. 3점 이하가 많으면 스토어/온보딩 카피 수정 필요.

## Q4. 유용성 (척도)
**"DueGuard 덕분에 실제로 놓쳤을지도 모르는 날짜를 지킬 수 있었다."**

실효성. 1~2점만 있으면 MVP 자체를 다시 봐야 함.

## Q5. 재방문 의사 (척도)
**"앞으로도 이 앱을 계속 쓸 것 같다."**

retention의 주관적 지표. 활성 지표(KPI)와 교차 검증.

---

## Q6. 7일 동안 등록한 항목 개수 (주관식, 숫자)
**"7일 동안 등록한 항목은 총 몇 개였나요? 그중 실제로 알림이 도움이 된 것은 몇 개였나요?"**

성공지표 "7일차 평균 항목 3건"과 매칭.

## Q7. 가장 놓치기 쉬웠던 항목 (주관식)
**"이번에 등록한 항목 중, DueGuard가 없었다면 가장 놓쳤을 것 같은 항목은 무엇이었나요? 왜 그런가요?"**

실제 "돈 나가는" 항목이 무엇인지. 타깃 사용자의 pain point 파악.

## Q8. 가장 헷갈리거나 불편했던 순간 (주관식)
**"사용 중 가장 헷갈리거나 불편했던 순간을 1~2개만 알려주세요."**

UX 문제 발견. 카피 / flow / 빈 상태 등을 바로잡기 위함.

## Q9. 없어도 됐던 기능 vs 꼭 필요한데 없는 기능 (주관식)
**"있어도 거의 안 쓴 기능이 있다면 무엇인가요? 반대로 꼭 필요한데 이번 버전에 없는 기능은 무엇인가요?"**

MVP 범위 검증. "하루 전/1시간 전 알림", "캘린더 연동" 등 우선순위 신호.

## Q10. 한 줄 평 (주관식)
**"이 앱을 한 문장으로 소개한다면?"**

포지션/카피 후보 수집. 스토어 설명과 마케팅 카피로 재활용 가능.

---

## 분석 기준

| 지표 | 합격 | 불합격 |
|---|---|---|
| Q1 평균 | ≥ 4.0 | < 3.5 (폼 UX 보완 필요) |
| Q2 평균 | ≥ 4.5 | < 4.0 (알림 로직 critical) |
| Q3 평균 | ≥ 4.0 | < 3.5 (카피/온보딩 수정) |
| Q4 평균 | ≥ 3.5 | < 3.0 (MVP 가설 재검토) |
| Q5 평균 | ≥ 3.5 | < 3.0 (retention 재설계) |
| Q6 중앙값 | ≥ 3건 | < 2건 |
| Q7~Q10 | 3명 이상 유사 패턴 반복되면 채택 |
