# DueGuard MVP Scope

## 한 줄 정의
DueGuard는 "놓치면 돈이 나가는 일정"을 로컬 알림으로 막아주는 안드로이드 앱이다.

## 포지셔닝
- "모든 일정 관리"가 아니다.
- "손실 방지"다.
- 비교 대상: 구글 캘린더, 일반 To-Do 앱이 아니라 "깜빡해서 돈 빠져나간 경험"이다.

## 핵심 사용자 문제
1. 청구서/세금/자동결제 날짜를 놓쳐서 연체료/위약금이 발생한다.
2. 무료 체험이 유료로 자동 전환되는 시점을 기억하지 못한다.
3. 구독/멤버십 갱신일을 모른 채로 몇 달째 자동결제되고 있다.
4. 카드 대금, 관리비, 통신비처럼 매달 반복되는 비용의 납부일이 머릿속에서 뒤섞인다.
5. 자동차 보험/정기점검/건강검진처럼 1년 단위로 돌아오는 일정을 놓친다.

위 5개는 전부 "놓치면 손해"라는 공통점을 가진다. DueGuard는 이 영역만 다룬다.

## MVP 포함 범위
- 항목 추가 / 수정 / 삭제
- 카테고리 선택 (고정 enum)
- 날짜+시간 선택
- 반복 주기: once, daily, weekly, monthly, yearly
- 로컬 알림 1회 예약 (항목당 다음 1회분)
- 다가오는 일정 리스트
- 완료 처리
- 완료 후 다음 회차 자동 생성 (반복 항목에 한함)
- ko/en 로컬라이즈드 UI 문자열

## MVP 제외 범위
- 로그인, 회원가입, 서버 API
- 클라우드 백업, 디바이스 간 동기화
- 가족/팀 공유
- 광고, 결제, 구독, 프로 플랜
- OCR, 이메일/SMS 파싱, 자동 구독 탐지
- iOS, 웹
- 고급 통계, 차트, 대시보드
- 스마트 추천, AI 자동 분류
- 복잡한 반복 규칙 (매월 마지막 평일, n번째 월요일 등)
- 여러 알림 (하루 전, 1시간 전 동시 예약 등) - 일단 1회만
- 타임존 변경 대응 (local device timezone만 사용)

## 망하는 버전 vs 되는 버전

| 항목 | 망하는 버전 | 되는 버전 |
|---|---|---|
| 포지션 | "일정을 다 관리해주는 앱" | "돈 나가는 일정만 지켜주는 앱" |
| 첫 화면 | 빈 캘린더 | "다음으로 돈 나갈 일정" 카드 |
| 항목 등록 | 제목/설명/태그/우선순위/반복/알림/메모 필드 전부 | 제목 + 날짜 + 카테고리 + 반복만 |
| 카테고리 | 자유 입력 | 고정 enum 6-8개 |
| 반복 규칙 | RRULE 전체 지원 | once/daily/weekly/monthly/yearly 5종 |
| 알림 | 하루 전, 당일, 1시간 전 다중 예약 | 항목당 다음 1회만 |
| 로컬라이즈 | 한국어 먼저 쓰고 나중에 번역 | 처음부터 ko/en 리소스 구조 |
| 데이터 | 서버/동기화/백업 | 디바이스 로컬 only (Isar) |
| 성공 지표 | DAU | 설치 후 첫 항목 등록까지 시간, 7일 재방문 |
| 첫인상 | "또 하나의 To-Do 앱" | "이거 안 깔면 돈 샌다" |

## DueGuard 이름 사용 이유
- "Due": 청구/기한/납부일이라는 금융 맥락을 즉시 환기한다.
- "Guard": 방어/차단의 이미지로, 능동적인 To-Do가 아니라 "방패" 역할을 강조한다.
- 한국어권에서도 영문 그대로 읽기 쉽고, 검색 시 겹치는 일반명사 앱이 적다.
- 대안 후보 (Bills/Subtrack/Moneyloss 등)는 범위가 너무 좁거나(청구서 전용) 부정적 단어라 탈락.

## 한국어 중심 MVP 검증 전략
- 1차 검증 대상은 한국 사용자다. 카피/예시/카테고리 명은 한국 상황 기준으로 작성한다.
  - 예: "카드 대금", "관리비", "넷플릭스 자동결제", "자동차 보험" 등
- 스크린샷, 스토어 설명, 피드백 수집도 한국어로 먼저 돌린다.
- 한국어 UX 안에서 "첫 항목 등록 15초 이내"가 가능해야 MVP 성공으로 본다.

## 영어 버전 원칙
- 영어는 **구조 대응만** 한다. 품질 부담은 최소화한다.
- 모든 UI 문자열은 ko, en 양쪽 리소스에 반드시 존재해야 한다. (하드코딩 금지)
- en 문구는 자연스러우면 좋지만, 네이티브 감수는 MVP 범위 밖.
- 카테고리/예시는 한국 맥락을 영어로 직역하지 않는다. (예: "관리비"는 "Maintenance fee"로, "자동차 보험"은 "Car insurance"로 최소 대응만)
- 영어 스토어 등록, 영어권 마케팅은 MVP 이후로 미룬다.

## 엔지니어링 원칙 (재확인)
- Flutter 로컬 앱. 서버 코드 추가 금지.
- local device timezone만 사용. 사용자의 디바이스 타임존이 바뀌면 재예약은 "다음 앱 실행 시 보정"으로 처리.
- 과한 clean architecture 금지. 폴더 3-4단 이내.
- 문자열 하드코딩 금지. ko/en 리소스 분리.
- MVP 범위를 벗어나는 반복 규칙(매월 마지막 평일, n번째 수요일 등) 추가 금지.
