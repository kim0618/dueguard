# DueGuard Post-MVP Gates

MVP 이후 DB 스키마 확장, 서버 동기화, 수익화 같은 "큰 결정"을
**언제** 착수할지 기준을 미리 정해둔다. 데이터 없이 결정하면 기능이 한없이 커진다.

원칙:
- MVP는 "돈 나가는 날짜 관리"에 한정.
- 지표가 합격선을 넘지 못하면 기능이 아닌 **포지션/카피**를 먼저 고친다.
- 아래 gate를 통과하지 못한 상태에서 해당 기능 착수 금지.

---

## Gate A: DB / 스키마 확장 (Isar 추가 필드)

**트리거 조건** (전부 충족):
- D7 retention ≥ 40%
- 설문 Q9에서 "필요한데 없는 기능"으로 특정 항목이 3명 이상에서 반복 언급
- 해당 항목이 MVP 포지션("돈 나가는 날짜")에서 이탈하지 않음

**해당 항목 예시**:
- 다중 알림(하루 전/1시간 전): 반복 언급 우선 후보
- 금액 필드: 카테고리별 집계 및 "이번 달 지출 예상액" 카드용
- 첨부 이미지(청구서 사진): OCR의 프리커서. 단, OCR은 별도 gate.

**작업 범위** (승인 시):
- Isar 컬렉션에 필드 추가 + 마이그레이션 (build_runner 재생성)
- ARB 키 추가
- 유닛 테스트 + QA 체크리스트 추가
- 기존 사용자 데이터 보존을 위해 nullable 필드로 추가

**Non-starter**:
- 별도 컬렉션을 만드는 복잡한 관계형 구조
- 사용자가 필드를 직접 정의하는 "custom fields"

---

## Gate B: 서버 동기화 / 백업

**트리거 조건** (둘 다 충족):
- Public 트랙 기준 DAU ≥ 500명
- 설문에서 "다기기 동기화" 요구가 전체 응답의 30% 이상

**해당 항목**:
- 익명 계정 기반 클라우드 백업 (Firebase Auth + Firestore 또는 자체 백엔드)
- 탈퇴 시 데이터 즉시 삭제
- 기기 1→2→N 동기화

**작업 범위** (승인 시):
- 스키마: 로컬 Isar ↔ 서버 스키마 맵핑 정의
- 인증: Google Sign-In 또는 Apple Sign-In만. 이메일 비밀번호 금지.
- 충돌 해결: last-write-wins (단순화) 또는 field-level merge (고급)
- 오프라인 우선 (Isar가 truth, 서버는 mirror)
- 개인정보 처리방침 재작성

**Non-starter**:
- 계정 없이 이메일만 입력받는 백업 (복구 경로 없음)
- 가족/팀 공유 (별도 gate)
- 서버가 truth가 되는 설계 (로컬 단독 사용이 불가능해짐)

---

## Gate C: 수익화 (광고 / 결제 / 구독)

**트리거 조건** (전부 충족):
- Public 트랙 기준 MAU ≥ 2,000명
- 30일 retention ≥ 25%
- 유료화 전환 가능한 "Pro" 기능 후보가 설문에서 1개 이상 구체화됨

**우선순위 정책**:
1. **구독(freemium)** > **일회성 구매** > **광고**
   - 광고는 앱 톤("놓치면 돈 나간다"와 상충)에 안 맞아 최후의 수단.
2. Pro 후보:
   - 다중 알림 (하루 전 / 3일 전 등)
   - 금액 집계 / 월 리포트
   - 클라우드 백업 (Gate B 통과 후만)
3. 무료 사용자는 항목 수 제한 **없음**을 원칙으로 한다.
   (핵심 가치인 "놓치지 않기"를 무료로 제공해야 의미 있음)

**작업 범위** (승인 시):
- 구독 플랜 구조 설계 (월/연 이중 가격, 7일 무료 체험)
- 결제 도구: Play Billing 전용. 자체 결제 금지.
- UX: 결제 유도는 "Pro 기능 탭 시에만" 노출. 홈 배너 남용 금지.
- 스토어 정책: 구독 해지 경로 명시

**Non-starter**:
- 리워드 광고 기반 알림 해제
- 전면 배너 광고
- 핵심 기능(CRUD/알림/반복)을 유료화

---

## Gate D: OCR / 이메일 자동 파싱

**트리거 조건** (전부 충족):
- Public 트랙 MAU ≥ 5,000명
- 설문에서 "항목 직접 입력이 귀찮다"는 불만이 40% 이상
- 법무 검토 완료 (메일 접근 권한은 Play 정책상 매우 엄격)

**해당 항목**:
- 청구서/영수증 사진에서 금액/날짜 추출 (OCR)
- 카드사 이메일 청구서 파싱

**Non-starter**:
- 공인인증서 기반 카드사 로그인 (법무 리스크 과다)
- 배경에서 무단으로 이메일 수신함 스캔

---

## Gate E: 웹 버전 / 다른 플랫폼

**트리거 조건**:
- iOS 수요 요청 20건 이상 → iOS 우선
- 웹 수요는 후순위 (모바일 알림 중심 앱이므로)

---

## 공통 원칙

- Gate 통과 후에도 **1개 기능씩** 붙인다. 한꺼번에 3개 추가 금지.
- Gate 통과 여부는 KPI 대시보드(`post-launch-kpi.md`)에서 판단.
- Gate 통과 전에는 요청이 들어와도 "로드맵에 있다"로만 응답하고 구현하지 않는다.
- 모든 Gate 착수는 사용자(PO)의 명시적 승인 후에만.
